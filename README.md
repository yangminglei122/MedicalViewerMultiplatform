# 医学影像浏览器(NAS 版)

运行在**群晖 NAS Web Station**上的 DICOM 影像阅读器:导入、浏览、导出医疗影像,电脑与手机浏览器均可使用。**无需 Docker、无需数据库、无需任何 Node/npm 构建**——纯静态前端 + 单文件 PHP 后端,拷贝即部署。

> ⚠️ 本软件适用于个人/家庭对自有医疗影像的管理与查阅,不能替代诊断工作站,请勿作为临床诊断依据。

## 功能

- **导入**:DICOM 文件多选、整个文件夹、ZIP 压缩包(服务器端解压);支持多患者混合导入,自动分组
- **患者信息确认**:导入时弹出患者姓名/ID/出生日期/性别,可**人工核对修改**后入库(应对 DICOM 中患者信息录入错误);自动识别中文字符集(GB18030/GBK/UTF-8),可手动切换;与库中已有患者自动合并,重复检查/图像自动去重
- **数据组织**:患者 → 多次检查 → 多序列 三级结构,**PACS 风格工作列表**:按患者分组的检查表格(检查日期/描述/检查号/设备徽章/序列与图像数),行内一键展开**序列缩略图条**;2D X 光、多序列 CT/MR、增强多期相、灌注等混合类型均可管理(多帧图像按帧数累计统计)
- **检索**:关键词(姓名/ID/检查名称/检查号)+ **检查日期范围** + **设备类型多选**(CT/MR/US/DX…按库内实际设备自动生成),即时过滤
- **阅片**:窗宽窗位(拖拽/预设:脑窗/肺窗/骨窗/软组织/纵隔)、缩放、平移、滚轮/滑动翻层、CINE 播放、反色、旋转、翻转、复位、1×1/1×2/2×2 多视图布局
- **MPR 多平面重建**:CT/MR 体数据一键生成 轴位/冠状/矢状 三视图,十字线联动定位(任一视图点击/拖动即同步其余两视图),支持 WW/WL、缩放、平移;按像素间距与层厚保持真实比例
- **测量标注**:长度(mm,自动用 PixelSpacing 校准)、角度、矩形/椭圆 ROI(面积、均值±标准差)、文字;标注支持拖动端点修改、选中删除;鼠标悬停图像时左下角实时显示**坐标 + 灰度值/HU**
- **导出**:检查/患者原始 DICOM 打包 ZIP 下载;当前视图导出 PNG
- **管理**:编辑患者信息、删除检查/患者、搜索、可选登录认证
- **压缩格式**:内置解析 显式/隐式 VR 小端、大端、Deflated、RLE、JPEG(baseline/extended)、**JPEG 无损(proc14/SV1,TS .57/.70)**、**JPEG-LS(TS .80/.81)**、多帧、调色板彩超、YBR;JPEG2000 不支持(需先转码)

## 目录结构

```
├── index.html          主页面
├── demo.html           演示页(生成模拟数据体验,不写库)
├── api.php             后端(唯一 PHP 文件)
├── config.php          可选配置(登录/数据目录,默认全注释=不启用)
├── css/  js/           前端(零依赖)
└── data/               运行时自动创建:索引 + DICOM 文件 + 临时目录
```

## 群晖 Web Station 部署(推荐)

### 1. 启用 Web Station
控制面板 → **Web 服务** (DSM 7 为「控制面板 → Web 服务」或「套件中心安装 Web Station」) → 启用主目录 `web` 共享文件夹。无需 MySQL/PHP 高级设置。

### 2. 上传程序
把本目录所有文件(不含 `dev/`)通过 **File Station**(拖拽上传)复制到共享文件夹 `web/medicalviewer/` 下。

### 3. 设置 PHP
Web Station → **脚本语言设置** → PHP 7.4 或 8.x,建议:
- **上传大小**:「上传文件大小上限」建议 ≥2048M(单个 DICOM/ZIP 可能达数百 MB);
- 「POST 最大值」≥ 上限;
- **max_input_time**:若自定义 PHP 配置可设为 `300`(秒),避免超大文件接收被掐断;
- **memory_limit** 建议 ≥512M(ZIP 解压流式处理,占用已很小,此项为保险);
- 扩展无需特别开启(zlib/json 为默认内置;mbstring 可选,缺失时自动降级)。

> 大文件说明:超过 24MB 的单文件与压缩包会自动改为 **8MB 分块上传**(逐块传输+断序保护),既避免单次超长请求被超时掐断,也显著提升吞吐;普通多文件仍为批量+3 路并发上传。

### 4. 数据目录权限
程序需要在 `web/medicalviewer/` 下创建 `data/` 目录。若首次访问提示"无法创建数据目录":

- **方式 A(DSM 7)**:控制面板 → 共享文件夹 → `web` → 编辑权限 → 在用户列表切换到「**系统内部用户**」→ 给 `http` 勾选「读写」;
- **方式 B(SSH)**:`chmod -R 770 /volume1/web/medicalviewer` 并 `chown -R http:http /volume1/web/medicalviewer`(控制面板→终端机启用 SSH 后 `sudo -i` 执行)。

### 5. 访问
浏览器打开 `http://群晖IP/medicalviewer/`。手机同样地址;可「添加到主屏幕」当 App 用(已适配移动端布局:序列侧栏变抽屉、工具栏横向滑动、双指缩放平移)。

### 建议加固(按需)
- **账号系统(内置)**:所有访问都需要登录。首次部署自动创建管理员 **admin / admin**,请登录后立即在顶栏「账号管理」中修改密码;管理员可创建/删除**临时账号**并设定有效期(1 天~1 年),到期自动失效(登录中与后续请求均拒绝),支持续期(+7 天)与改密。账号存储在 `data/accounts.json`(密码为单向哈希)。
- **HTTPS**:DSM 控制面板 → 登录门户 → 高级 → 反向代理,把 `medicalviewer.你的域名` → `http://localhost/medicalviewer/`,并套用 DSM 证书;手机在公网访问务必走 HTTPS;
- 若 Web Station 后端为 **Apache**,`data/` 已自动放置 `.htaccess` 禁止直接访问;若为 **Nginx**,DICOM 文件虽不可枚举(文件名为 UID),稳妥起见可将 `config.php` 中 `MV_DATA_DIR` 指向 web 之外的目录,如 `/volume1/medicalviewer-data`(需先创建并按第 4 步授权)。

## 本地/其他 PHP 主机部署

任意支持 PHP 7.4+ 的环境(Apache/Nginx + PHP)都可直接部署本目录。本地测试:

```
php -S 0.0.0.0:8160 -d upload_max_filesize=2048M -d post_max_size=2100M -d max_input_time=-1 -d memory_limit=1024M -t .
```

访问 http://127.0.0.1:8160/ ,先打开 `demo.html` 生成演示数据体验。

## 使用说明

### 工作列表(患者/检查检索)
- 列表页按患者分组显示全部检查;点击检查行直接打开阅读器;
- 点击行首箭头可**展开序列缩略图条**(多于 14 个序列时折叠显示);
- 检索:关键词(姓名/ID/检查名称/检查号)、日期范围、设备类型多选,组合使用即时过滤;
- 患者行可编辑信息、导出全部检查、删除患者;检查行可导出 ZIP、删除。

### 导入
点击右上角「导入」→ 选择文件(.dcm/.zip)/整个文件夹,或直接把文件/文件夹**拖入窗口**:
1. 浏览器解析全部文件,按患者分组;
2. **逐组弹出确认**:核对姓名/ID/生日/性别(可修改;中文乱码时切换字符集),检查描述/日期可编辑;已存在的检查默认跳过(可改为合并);
3. 「仅预览」= 不入库直接阅片;「确认导入」= 上传入库(批量+多路并发,进度显示实时速度);
4. 多个患者会依次确认;结构化报告(SR)/注释(PR)等**非图像对象自动跳过**并提示;
5. **同名患者提示**:姓名与库中已有患者相同时,可一键采用该患者的 ID/生日/性别(合并档案);

### 数据安全
- `data/` 目录即全部数据(索引 + 原始 DICOM),**备份该目录即备份全部影像**;
- 原始 DICOM 文件不做任何修改;患者信息修正仅存于索引 `index.json`;
- 换新 NAS/迁移:整个目录拷走即可。

## 已知限制
- JPEG 2000 / JPEG-LS 压缩的 DICOM 需先在工作站转为未压缩或普通 JPEG;
- 多帧封装 JPEG 的帧定位依赖 Basic Offset Table(绝大多数设备提供);
- 容量建议:数万幅图像(约 20–50GB)内响应良好;更大规模建议按年份分目录部署多套;
- Chrome/Edge/Safari 近年版本均可;IE 不支持。

## 开发与测试
`dev/` 目录为开发辅助(本地 PHP、脚本),部署时无需上传。`demo.html` 在浏览器内合成模拟 CT/MR 数据(纯前端,不写库),用于体验与回测。
